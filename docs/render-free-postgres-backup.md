# نسخهٔ پشتیبان پایگاه دادهٔ رایگان Render

## وضعیت و مهلت

پایگاه دادهٔ فعلی ثریا روی پلن Free قرار دارد و Render تاریخ انقضای آن را **۲ دسامبر ۲۰۲۶** اعلام کرده است. پایگاه داده‌های Free پس از ۳۰ روز منقضی می‌شوند، در پلن Free نسخهٔ پشتیبان خودکار و خروجی از داشبورد در دسترس نیست و پس از انقضا فقط ۱۴ روز برای ارتقا فرصت وجود دارد؛ پس از پایان مهلت، داده‌ها حذف می‌شوند.

این runbook برای گرفتن یک خروجی منطقی با `pg_dump` و نگهداری **رمزشده** آن در GitHub Actions آماده شده است. هیچ خروجی‌ای به‌صورت متن خام در مخزن یا Artifact ذخیره نمی‌شود.

## آماده‌سازی یک‌باره در GitHub

در مخزن `botriz/Suraya-ai`:

1. پس از ادغام این تغییر، به **Settings → Secrets and variables → Actions** برو.
2. یک Secret با نام `SURAYA_DATABASE_URL` بساز و مقدار **External Database URL** پایگاه دادهٔ Render را در آن قرار بده. این مقدار را در چت یا فایل مخزن قرار نده.
3. روی گوشی یک کلید ۳۲ بایتی تصادفی بساز. در Termux با Node.js:
   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```
   خروجی ۶۴ نویسه‌ای را در جای امن خودت نگه دار.
4. یک Secret دیگر با نام `SURAYA_BACKUP_ENCRYPTION_KEY` بساز و همان کلید ۶۴ نویسه‌ای را در آن قرار بده. کلید را گم نکن؛ بدون آن فایل پشتیبان قابل بازیابی نیست.

## اجرای نسخهٔ پشتیبان

1. به **Actions → Encrypted Suraya PostgreSQL backup → Run workflow** برو.
2. در فیلد تأیید دقیقاً `BACKUP` بنویس.
3. پس از موفقیت، Artifact با نامی شبیه `suraya-postgres-encrypted-backup-<run-id>` ظاهر می‌شود.
4. فایل `suraya.dump.enc` و `SHA256SUMS` را دانلود و در یک محل امن نگهداری کن. Artifact پس از ۳۰ روز منقضی می‌شود؛ فایل دانلودشده را نگه دار.

Workflow از PostgreSQL 18 client استفاده می‌کند، آرشیو را با `pg_restore --list` بررسی می‌کند، با AES-256-GCM رمز می‌کند و سپس رمزگشایی و صحت‌سنجی رمزنگاری را نیز آزمایش می‌کند. فقط فایل رمز‌شده بارگذاری می‌شود.

## بازیابی روی دستگاه یا سرور مقصد

به Node.js و PostgreSQL 18 client نیاز است. کلید ۶۴ نویسه‌ای را فقط در محیط امن همان دستگاه وارد کن:

```bash
export BACKUP_ENCRYPTION_KEY='YOUR_64_HEX_CHARACTER_KEY'
node scripts/backup/decrypt.mjs suraya.dump.enc suraya.dump
pg_restore --list suraya.dump
```

برای بازیابی در یک پایگاه دادهٔ خالی:

```bash
pg_restore --dbname="$NEW_DATABASE_URL" --no-owner --no-privileges suraya.dump
```

**هشدار:** فرمان بازیابی را فقط روی پایگاه دادهٔ خالی اجرا کن. از گزینه‌های `--clean` یا `--if-exists` استفاده نکن، مگر اینکه حذف اشیای مقصد را عمداً بررسی و تأیید کرده باشی.

## مرزهای ایمنی

- این workflow فقط با اجرای دستی و واردکردن عبارت `BACKUP` شروع می‌شود.
- هیچ داده‌ای را در پایگاه داده تغییر نمی‌دهد؛ `pg_dump` فقط خروجی می‌گیرد.
- فایل خام موقت پس از رمزنگاری حذف می‌شود و در Artifact بارگذاری نمی‌شود.
- رمزگشایی فقط با همان کلید ۳۲ بایتی ممکن است.
- تا زمان بررسی فایل و آزمایش بازیابی، پایگاه دادهٔ Render را حذف نکن.
- این راهکار جایگزین نسخهٔ پشتیبان دوره‌ای و آزمون بازیابی نیست.
